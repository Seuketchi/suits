## What it does

`ask-donna` is the front desk as a command. You describe your situation in plain words, and it tells you who to ask and what to type. Its answer has four parts, verdict first: the one character who owns the job, the exact commands in order, what comes back, and, when you fit one, the matching page in [the guides](../guides/README.md).

It names one owner, never two. A bug goes to rachel first, for the trigger and the causes. If the work moves on to someone else after the first character hands back, the next command comes as a second line, marked as coming after. If your situation is too thin to route, it asks one question and then routes.

It does no work. It drafts nothing, runs no tool and starts no session. It names only commands that ship in this plugin.

## When to reach for it

When you are not sure which character or command fits: "I'm writing a grant proposal and the deadline is Friday." Type `/suits:ask-donna` followed by the situation. Skip it when you already know who to ask; go straight to that character.

## Common questions

**How is it different from asking donna?**
Asking donna with `/suits:donna` gets the request logged and the work started. `ask-donna` only tells you where the work belongs and what to type. Nothing is written or started.

**Why can't a character call it?**
It is a skill only a person starts. A character already knows who it hands work to.

**Can it name two characters for one ask?**
Not as owners. When a job runs through two characters in turn, the second command comes after the first character hands back.

**What if I describe too little?**
It asks one question, then answers.

## It's working if

- The first line names one character as the owner.
- The command is ready to paste and carries your own details.
- Every command it names ships in this plugin.
- A bug goes to rachel first.
- A guide is linked only when you fit one.
- Nothing is drafted, run or started by the answer.
