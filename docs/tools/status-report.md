## What it does

`status-report` writes the one-page status for a piece of work, in a fixed order: the state with the one before it and the as-of date, the dates (baseline, last reported, current) and why each moved, the decision needed, the top three risks, what is done by scope, what is next, and usage against the cap when the forecast is over it. The state is set by the dates: on track, at risk, blocked or replan. There is no percent complete and no count of closed tickets as progress.

## When to reach for it

When the owner or a stakeholder needs a status. Jessica calls it; donna lays the result out or puts it on the owner's brief.

## Common questions

**Why is the decision line near the top?**
Because the reader must act on it. It is within the first five lines, either as `Decision needed: <what, by whom, by when>` or `No decision needed`.

**What if a claim is not on the board?**
It is marked `assumed` and has a row in the risk log.

**Why no percent complete?**
At the start of unknown work the number has no meaning. The report says what is done, what is still unknown and what has not moved.

## It's working if

- The state is on the first line, with the one before it and an as-of date.
- Every date is labelled baseline, forecast or actual.
- A decision line is in the first five lines.
- A moved date carries a reason.
- There is no percent complete.
